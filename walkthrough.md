# Walkthrough: Реализация строгой проверки полноты эмиссионных документов

## Описание изменений

В рамках данной задачи была реализована система строгой проверки полноты обработки эмиссионных документов, а также добавлена возможность автоматического удаления исходных файлов после успешной конвертации.

### Основные компоненты и изменения:

1.  **`conversion_service/app/routers/emission_doc_download.py`**:
    *   В эндпоинт `POST /emission-doc-download/run` добавлены query-параметры:
        *   `force_recheck: bool = Query(False, ...)` — для запуска глубокой проверки.
        *   `keep_source_files: bool = Query(True, ...)` — если передать `False`, исходные файлы (PDF, DOC, DOCX, RTF) будут удалены после успешной конвертации.

В рамках данной задачи была реализована система строгой проверки полноты обработки эмиссионных документов. Основная цель — гарантировать, что все документы, указанные в базе данных для конкретной облигации, не только отмечены как обработанные в манифесте, но и физически присутствуют на диске в формате Markdown (.md).

### Основные компоненты и изменения:

1.  **`conversion_service/app/services/bonds_service.py`**:
    *   Добавлена функция `get_all_bonds_metadata`, которая позволяет пакетно получить ИНН и регистрационные номера для всех облигаций. Это оптимизирует процесс проверки, исключая тысячи одиночных запросов к БД.

2.  **`conversion_service/app/repository/db/emission_document_repository.py`**:
    *   Добавлен метод `get_all_documents_by_metadata`, который пакетно извлекает все URL документов из таблицы `emission_documents`, группируя их по паре (ИНН, рег. номер).

3.  **`conversion_service/app/services/emission_doc_download_service.py`**:
    *   **`_is_bond_fully_processed`**: Внедрен строгий алгоритм проверки. Теперь проверяется не только флаг в манифесте, но и:
        *   Статус каждой записи (`completed`).
        *   Отсутствие ошибок (`error: null`).
        *   Наличие файлов в списках `files` и `converted_files`.
        *   **Физическое наличие `.md` файлов на диске** для каждого документа, подлежащего конвертации.
    *   **`download_and_convert`**: Добавлена поддержка параметра `force_recheck`. При его включении метаданные загружаются пакетно, и для каждой облигации запускается детальная проверка.
    *   **`_process_single_bond`**: Обновлена логика инициализации. Если при проверке обнаружено отсутствие физического файла или несоответствие критериям, статус записи в манифесте сбрасывается в `error`, что инициирует повторную загрузку и конвертацию.

4.  **`conversion_service/app/routers/emission_doc_download.py`**:
    *   В эндпоинт `POST /emission-doc-download/run` добавлен query-параметр `force_recheck` (по умолчанию `false`).

## Результаты тестирования

### Сценарий 1: Обычный запуск (`force_recheck=false`)
*   Система проверяет флаг `fully_processed` в манифесте.
*   Если флаг `true`, облигация пропускается мгновенно.
*   **Результат**: Высокая скорость работы при повторных запусках.

### Сценарий 2: Строгая проверка (`force_recheck=true`)
*   Система игнорирует флаг `fully_processed` и выполняет детальный аудит.
*   При ручном удалении одного `.md` файла и запуске с `force_recheck=true`:
    1.  Логи фиксируют неполноту данных.
    2.  Флаг `fully_processed` в манифесте сбрасывается в `false`.
    3.  Система обнаруживает недостающий файл, скачивает исходник (если его нет) и заново конвертирует его.
    4.  По завершении флаг `fully_processed` снова становится `true`.
*   **Результат**: Гарантированная целостность данных в хранилище.

## Инструкция по использованию

Для запуска полной перепроверки всех облигаций (например, после сбоя файловой системы или обновления алгоритма конвертации) используйте:

```bash
curl -X POST "http://localhost:8000/emission-doc-download/run?force_recheck=true"
```

Или через Swagger UI на странице микросервиса.
